# COMP7506 Group Project 调研汇总

> 汇总截至 2026-09-14 的全部调研(对应 Multica issue CAO-231)。任务书原文见本目录 `COMP7506_Group_Project_2026.pdf` 与 `COMP7506_Grade_Descriptor.pdf`。

## 0. 任务书要点

- 占总成绩 **40%**;迟交每天扣 10%,扣到 0 为止
- 关键节点:**组队 9/27(周日)**(Moodle 分组,每组最多 6 人;2 人以上组每人交 Peer Review Form)→ **演示 11/19(周四)最后一堂课** → **最终交付 11/30(周一)23:59**
- 交付物:文档(≥2 页:背景调研至少 3 款同类 App + 应用概述 + 各成员贡献)15% / 1-2 分钟介绍视频 15% / 源代码 + readme 5% / 最后一课演示 5%
- 技术范围:Android Studio / Xcode / React Native / Flutter / Unity / Unreal 均可,hybrid、小程序可接受;服务端可用 PHP、Python 等
- 复杂度与人数匹配:6 人组做综合应用,2 人组可做较简单应用

## 1. 总体策略判断

**源代码只占 5%,文档 15% + 视频 15% + 演示 5% = 35% 全在"讲故事和演示"上。** 选题优先级:好演示 > 动机/调研好讲 > 技术炫技。演示(11/19)早于交付(11/30),演示版本基本就是最终版,视频用演示录屏剪即可。

## 2. 候选选题(5 个,按推荐度排序)

技术栈统一建议 **Flutter + FastAPI(Python)**:一套代码双端演示,队友不用分 Android/iOS 两摊;后端是 owner 强项可直接接管;Flutter 对新手文档友好。游戏除外。

### A. HKU 校园通(Information)— 最稳
- 核心功能:校园地图+楼宇导航、食堂菜单/人流、校巴时刻、空教室查询、活动时间线
- 弹性:2 人=离线静态版 3 功能(地图+校巴+食堂);4 人=+FastAPI 后端聚合+空教室;6 人=+账号系统+人流众报+推送
- 优势:数据公开好拿、演示直观;调研对象现成(HKU 官方 App 及各校同类)

### B. MSc(CS) Connect 校友连接(Social)— 任务书原文方向
- 核心功能:校友/在读资料卡、按课程与求职方向匹配、mentorship 预约、内推分享板
- 弹性:2 人=名录+兴趣匹配;4 人=+聊天/预约;6 人=+推荐逻辑+活动管理
- 优势:动机故事天然("连接校友"),和 RA/求职线协同;注意隐私,MVP 用假数据+邀请制

### C. 刷题学习伴(Learning)— 自己备考也能用
- 核心功能:闪卡+间隔重复、程序填空刷题模式(直击本课开卷考套路)、学习小组匹配、番茄钟统计
- 弹性:2 人=纯本地 SQLite 刷题+闪卡;4 人=+账号同步+小组;6 人=+接 LLM API 自动出题
- 调研对象清晰:Anki、Quizlet 及各类刷题 App

### D. 香港行山周末通(Information/Lifestyle)— 差异化好做
- 核心功能:路线库(难度/时长/到起点的交通)、天气适宜指数、渡轮巴士班次、结伴组队、打卡成就
- 弹性:2 人=静态路线库+天气;4 人=+地图轨迹+结伴;6 人=+成就系统+分享
- 调研对象:AllTrails、TrailWatch、香港远足路线类 App

### E. 茶餐厅大亨(Game/Entertainment)— 演示效果最好
- 核心功能:模拟经营核心循环(点单/出餐/升级)、港式美食图鉴、每日挑战、排行榜
- 技术栈:Unity(任务书点名)或 Flutter Flame;纯单机可不要后端
- 弹性:2 人=单场景核心循环;4 人=+升级+图鉴;6 人=+排行榜后端+多店铺
- 风险:美术与调优耗时不可控,代码量大——但记住代码只占 5%

**私教个人排序:A > C > B > D > E**(A 和 C 的"故事-调研-演示"链条最顺)。

## 6. 技术栈专题:Flutter + FastAPI vs 原生,真机是否必要

结论:**Flutter,后端按需再上 FastAPI;真机不必要。**

### 6.1 为什么 Flutter(理由按权重排)

- **队友电脑是决定性未知量**:原生 iOS = Xcode = 只能 Mac 开发。组里只要有一个 Windows 队友,原生 iOS 直接出局。原生 Android(Android Studio)三平台都能装,但锁死单端。拍板前唯一要确认的事:**群里问一句"谁不是 Mac"**。
- **Flutter 任何电脑都能写**(Mac/Windows/Linux);Windows 队友也能用 Android 模拟器跑和调。演示日 iOS、Android 端任选。
- **分数结构**:一套代码两端可演示,视频素材和现场演示都不受设备限制。
- **简历线**:Flutter + FastAPI(Python)是完整自洽的全栈故事,后端 owner 可直接接管。
- 原生唯一诱惑是跟课件对齐,但小作业和工作坊已给原生 exposure,大项目以产出为先;Dart 对后端背景几乎没门槛。
- 一句话:就算确认全员 Mac 仍建议 Flutter;有 Windows 队友,Flutter 就是唯一合理选项。

### 6.2 "选 Android 但全员 iPhone"——真机不必要

- **模拟器足够覆盖这门课的一切**:Android Emulator、iOS Simulator(Mac 自带)都免费都快;评分四项没有一项要求真机。
- **录屏反而模拟器更干净**:没有通知弹窗、没有电量焦虑。演示日建议"**提前录好视频保底 + 现场模拟器演示**",别把成败押在真机连线上。
- **真机只在一种情况必要**:功能硬依赖硬件(蓝牙、NFC、相机扫码、GPS 轨迹、陀螺仪)。设计时留心:**核心流程不要绑死硬件**;这类功能做成锦上添花、可降级(没硬件时给模拟数据)。
- 若真走原生 Android 而全员 iPhone,模拟器就是唯一测试途径——同样的模拟器工作流,Flutter 还白送一个 iOS 端。

### 6.3 会上拍板建议

把"队友电脑情况"加进行政议程:全员 Mac → 仍建议 Flutter;有 Windows → Flutter 或原生 Android 二选一(还是建议 Flutter)。5 分钟收掉,别恋战。

## 7. 往届优秀作品墙调研(facebook.com/comp7506,2026-09-14)

该页面是 TW Chim 的官方优秀作品展示墙("excellent works done by our COMP7506 students",136 粉),内容为 2025-26 Class D 各组演示视频 reel(1–6 分钟/条),帖子只有 "Group NN" 编号没有文字说明,信息全在视频封面帧。

**实用工具类(主流):**
- **NextHome**:租房助手——"HKU 学生、预算 8,000、30 分钟通勤"直接命中本届痛点;AI 对话找房、房源对比表、租屋流程清单;UI 完成度很高

- **BreadCrumbs**:位置记录类(Windows 上的 Android 模拟器录制)

**游戏类(少数派但存在):** 有一个 3D 恐怖生存游戏(血量/SAN 值/摇杆/剧情对话,Unity 范儿)——选游戏路线有先例,也能进优秀墙。

**三个直接可用的结论:**

1. **AI 功能已是优秀作品标配**:LLM 设置页(自定义 API key/endpoint)、AI 出题、AI 对话助手到处可见。方案里建议内置一个 AI 亮点功能——成本就是接个 API,演示效果拉开档次。
2. **赛道校准**:C(刷题学习伴)和 Memora/InterviewMate 撞型——赛道被认可,但必须差异化;D(行山)、B(校友连接)墙上没有,差异化空间大但要自己论证需求;A(校园通)无直系撞车,但 NextHome 已示范"学生生活痛点+AI"打法有多吃香。
3. **视频形态可以是武器**:多数是模拟器直接录屏,但有一组做成电影感宣传片(AI 生成引入镜头+演示),也有直接用会议录屏交的——15% 的视频分上下限差距巨大。
